# Contributor Code of Conduct

OIDF discussions should be technically rigorous, respectful, and useful to
people working across infrastructure, commissioning, safety, and open source.

## Expected

- Explain disagreements with evidence and clear contract reasoning.
- Welcome contributors with different domain backgrounds.
- Keep proposals scoped to the OIDF format boundary.
- Protect private operational, customer, and site information.

## Not acceptable

- Harassment, discrimination, threats, or personal attacks.
- Publishing secrets, private coordinates, customer details, or deployment data.
- Claiming OIDF grants permits, AHJ approval, certification, energization
  authority, or permission to operate.
- Adding runtime or control behavior to the format repository.

Report concerns privately to the repository maintainers through GitHub.
